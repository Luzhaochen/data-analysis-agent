## 详细说明

### 1. 快速开始顺序会让全新环境建库前执行 `USE jd_demo` 而失败

**现象**

`README.md` 当前快速开始顺序是：

```powershell
mysql -u root -p < mock_data/schema.sql
mysql -u root -p < mock_data/alter_promo.sql
copy mock_data\setup.sql.example mock_data\setup.sql
mysql -u root -p < mock_data/setup.sql
```

但 `mock_data/schema.sql` 开头是：

```sql
USE jd_demo;
```

而真正创建数据库的语句在 `mock_data/setup.sql.example` 中：

```sql
CREATE DATABASE IF NOT EXISTS jd_demo CHARACTER SET utf8mb4;
```

如果是在一个还没有 `jd_demo` 数据库的新环境按 README 顺序操作，第一条命令就会报 `Unknown database 'jd_demo'`。

**建议**

调整顺序为：

1. 先创建数据库，再建表；
2. 或者在 `schema.sql` 开头显式加入 `CREATE DATABASE IF NOT EXISTS jd_demo; USE jd_demo;`；
3. README 与 SQL 文件应保持同一条可执行路径。

**处理结果**

已采用第 2 种方案：`mock_data/schema.sql` 现在会自动创建 `jd_demo` 库后再 `USE jd_demo;`，README 快速开始中的执行顺序已同步。

### 2. `schema.sql` 与 `alter_promo.sql` 存在重复字段

**现象**

`mock_data/schema.sql` 中的 `promo_calendar` 表已经包含：

```sql
activity_theme VARCHAR(64) NULL COMMENT '...'
duration_days INT NULL COMMENT '...'
```

但 `mock_data/alter_promo.sql` 又要执行：

```sql
ALTER TABLE promo_calendar
  ADD COLUMN activity_theme VARCHAR(64) NULL ...,
  ADD COLUMN duration_days INT NULL ...;
```

按 README 顺序先建表、再执行 alter，会触发：

```text
Duplicate column name 'activity_theme'
```

**建议**

二选一：

- 保留 `schema.sql` 中的字段，删除或废弃 `alter_promo.sql`；
- 或者让 `schema.sql` 不包含这两个字段，由 `alter_promo.sql` 负责增量加列。

目前两个文件职责重叠，README 中的执行顺序也需要同步修正。

**处理结果**

已采用第一种方案：`schema.sql` 保留 `activity_theme` 与 `duration_days` 字段，`mock_data/alter_promo.sql` 已删除，README 中相关步骤与目录说明已移除。

### 6. 自动追加 LIMIT 时，分号后带行注释的 SQL 可能被改写错误

**现象**

经复核，该案例不成立。

输入 `SELECT 1; -- comment` 会在更早的单语句检测阶段被拦截：`has_trailing_content_after_semicolon()` 检查到分号后仍有内容 `-- comment`，会判定为多语句并返回 `SYNTAX_ERROR`，因此根本不会进入 `append_limit()`。

`append_limit()` 中的行注释分支处理的是“无分号 + 尾注释”场景，例如：

```sql
SELECT * FROM orders -- comment
```

这个场景的改写是正确的。

**保留建议**

无需修改代码，但建议在 Phase 5 回归用例中加入该输入，专门防止未来重构时调整检查顺序或误删单语句检测。
