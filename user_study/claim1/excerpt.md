# 知识库摘录（核查参考）

> 来自团队分析助手的知识库。核查口径时请查这里。**不需要业务背景**——你的任务是看"口径说明"和这里的记载是否一致。

## 术语速览

| 术语 | 含义 |
|---|---|
| GMV | 总实付金额（买家实际支付的金额合计） |
| 客单价 | 平均每个订单的金额 = GMV ÷ 订单量 |
| cancelled | 订单状态之一：已取消 |
| 退款率 | 退款金额占 GMV 的比例 |
| 归属 | 一笔交易算到哪一天（按哪个日期字段统计） |
| 自然期 / 促销期 | 没有促销活动参与 / 有促销活动参与 |

## orders（订单表）

- **时间字段**：order_dt（DATE，覆盖 2025-01-01 ~ 2026-08-31）；所有查询必须带 order_dt 过滤。
  大促日支付可能跨天（pay_dt），**口径统一归属按下单日 order_dt**。
- **指标口径**：
  - GMV（默认·下单口径）：SUM(pay_amt)（order_status <> 'cancelled'）——**含 refunded**（退款订单曾成交）
  - 净成交额（完成口径）：SUM(pay_amt)（order_status = 'completed'）——严格已完成，排除退款
  - 有效订单量：COUNT(*)（order_status <> 'cancelled'）
  - 客单价：**GMV / 订单量**（与所取 GMV 口径配套，口径必须一致）
  - 自然期 GMV：SUM(pay_amt)（order_status <> 'cancelled' **AND promo_id IS NULL**）
- **注意事项/坑**：
  - 一个订单可含多 SKU → 与 order_items 关联聚合必须先按 order_id 去重（或先聚合再 JOIN）
  - cancelled 订单 pay_amt = 0 且无 pay_dt → 金额口径漏过滤会把 0 摊薄均值

## refunds（退货表）

- **时间字段**：refund_dt（DATE，实测覆盖 2024-12-31 ~ 2026-09-14）；所有查询必须带 refund_dt 过滤。
  退款归属口径 = **退款发生日**；如需按「原订单下单时间」归属，JOIN orders 用 order_dt（两种口径结果不同，先与用户确认）。
- **字段索引**：refund_dt 上的索引名为 **idx_dt**
- **指标口径**：
  - 退款金额：SUM(refund_amt)（按 refund_dt 归属；本表无状态字段，无需状态过滤）
  - 退款笔数：COUNT(*)（一个订单可有多笔退款，勿用 COUNT(DISTINCT order_id)）
  - 退款率（跨表，**待确认**）：退款金额 / 同时期 GMV（orders 口径）——归属时间口径（退款日 vs 下单日）需与业务确认后再使用
- **注意事项/坑**：
  - 脏数据（已定位）：refund_id ∈ {1, 2, 3} 共 3 条，refund_dt = '2024-12-31' 早于其原订单下单日 '2025-01-01'
    → 查询区间含 2024-12-31 或跨表对账时先剔除/标注；**2025-01-01 起的区间不受影响**
