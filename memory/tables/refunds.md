# refunds 退货表

- 用途：每笔退款的金额/时间/原因；回答「退款金额构成、退款原因分布、退款率（跨表）」类问题
- 粒度：一行 = 一笔退款单；唯一键 refund_id；与 orders 是 N:1（一个订单可产生多笔退款）
- 时间字段：refund_dt（DATE，实测覆盖 2024-12-31 ~ 2026-09-14）；**所有查询必须带 refund_dt 过滤**。
  退款归属口径 = 退款发生日；如需按「原订单下单时间」归属，JOIN orders 用 order_dt（两种口径结果不同，先与用户确认）
- 字段表：

| 字段 | 类型 | 含义 | 口径/取值 | 备注 |
|---|---|---|---|---|
| refund_id | BIGINT | 退款单ID | 唯一 | 主键 |
| order_id | BIGINT | 原订单号 | — | 关联 orders（idx_order） |
| refund_dt | DATE | 退款日期（时间过滤字段） | — | 所有查询必须过滤（idx_dt） |
| refund_amt | DECIMAL(12,2) | 退款金额（元） | 实测单笔 178.43 ~ 43,060.15 元，全为正 | 直接 SUM；本表无状态字段，无需状态过滤 |
| refund_reason | VARCHAR(64) | 退款原因 | 枚举（实测全表仅 5 种）：价格保护 / 物流破损 / 不想要了 / 七天无理由 / 质量问题 | 列 NOT NULL，无空值 |

- 指标口径：
  - 退款金额：SUM(refund_amt)（按 refund_dt 归属；本表无 cancelled 类状态，无需状态过滤）
  - 退款笔数：COUNT(*)（一个订单可有多笔退款，勿用 COUNT(DISTINCT order_id)）
  - 退款率（跨表，待确认）：退款金额 / 同时期 GMV（orders 口径）——归属时间口径（退款日 vs 下单日）需与业务确认后再使用
- 注意事项/坑：
  - 脏数据（已定位）：refund_id ∈ {1, 2, 3} 共 3 条，refund_dt = '2024-12-31' 早于其原订单下单日 '2025-01-01'（合计 35,337.11 元）→ 查询区间含 2024-12-31 或跨表对账时先剔除/标注；2025-01-01 起的区间不受影响
  - 数据边界：refund_dt 比 orders 覆盖范围（2025-01-01 ~ 2026-08-31）在两端各多出几天（前端 2024-12-31 即脏数据，后端 2026-09-01~14 为正常滞后退款）→ 按退款日统计与按订单表统计的区间天然对不齐，跨表比较时注意
  - 与 orders 是 N:1 → 聚合退款金额在 refunds 侧做，不要 JOIN orders 后直接 SUM（按订单行膨胀）；2026 上半年实测孤儿退款单 0、退款额超订单实付额 0、取消订单退款 0，历史全量未逐一验证，跨表对账前先 LEFT JOIN 探孤儿
  - 金额字段全为正、无负值 → 若后续发现负值/超额，先定位脏数据（参照 orders.md 坑 3 的处理思路），不要直接改口径
- 常用过滤：
  - `refund_dt >= 'YYYY-MM-DD' AND refund_dt < 'YYYY-MM-DD'`（左闭右开，必须带）
  - `refund_reason = '质量问题'`（按原因下钻；全表枚举见字段表）
- 关联键：
  - order_id → orders.order_id（N:1；跨表先按 refunds 侧聚合再 JOIN，或 LEFT JOIN 探孤儿退款单）
